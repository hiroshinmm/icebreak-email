# 配信重複防止機能の実装計画

この計画では、前回の配信内容と重複するニュース記事をスキップし、次の候補を配信する機能を実装します。

## 課題
現在、各カテゴリーから取得した最初のニュース記事が配信されています。しかし、同じ記事が数日間ニュースフィードに残っている場合、連続して同じ内容が配信されてしまう可能性があります。これを防ぎ、常に新しい、または別の視点を提供できるようにします。

## 提案する変更
配信済みの記事 URL を `config/history.json` に保存し、次回のフェッチ時にその履歴に含まれる記事をスキップして次の候補を選択するように修正します。

### `src/historyManager.js` [NEW]
- 配信済み記事の URL と配信日時を記録。
- ニュースの取得期間（10日間）に合わせて、古い履歴を自動的に削除する機能を実装。
- `loadHistory`, `saveHistory`, `updateHistory` などの関数を提供。

### `src/newsFetcher.js` [MODIFY]
- `fetchTopics` 関数に履歴データを渡し、各ソースごとに「履歴にない最初の記事」を選択するロジックに変更。

### `index.js` [MODIFY]
- メインプロセスで履歴を読み込み、`fetchTopics` に渡す。
- メール送信が正常に完了した後、新しく配信した記事の URL を履歴に追加して保存。

## 検証計画
### 自動テスト / 手動検証
- 履歴ファイルに特定の URL を含めた状態で実行し、その記事がスキップされて次の候補が選ばれることを確認。
- 合致する記事が複数ある場合、次のインデックスの記事が採用されることを確認。
- 該当する記事が全て重複している場合、既存の「ニュースがありません」という挙動になることを確認。
